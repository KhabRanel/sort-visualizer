# Функциональные требования к MVP

## Use case 1. Пошаговый просмотр работы алгоритма сортировки

**Актор:** пользователь: студент, изучающий алгоритмы сортировки.

**Предусловия:**
- приложение открыто в современном браузере;
- пользователь находится на странице «Алгоритмы» (`/algorithms`).

**Основной сценарий:**
1. Пользователь выбирает алгоритм в списке, например «Быстрая сортировка».
2. Приложение открывает страницу `/algorithms/quick`. На ней массив из 30 случайных чисел показан в виде столбчатой диаграммы.
3. Пользователь выбирает вид исходных данных («Почти отсортированный») и размер массива. Приложение сразу генерирует новый массив.
4. Пользователь нажимает «Старт».
5. Приложение по шагам воспроизводит работу алгоритма:
   - сравниваемые элементы выделяются одним цветом, переставляемые - другим, элементы на своём месте - третьим;
   - счётчики сравнений и перестановок обновляются на каждом шаге.
6. Пользователь меняет скорость ползунком. Анимация продолжается с новой скоростью.
7. Анимация заканчивается, когда массив отсортирован. Все столбцы выделяются как отсортированные, кнопка «Старт» становится недоступна до сброса.

**Результат:** пользователь увидел, как алгоритм упорядочивает массив, и знает, сколько сравнений и перестановок для этого понадобилось.

**Альтернативные сценарии:**
- **4а. Пошаговый режим.** Пользователь нажимает «Шаг» вместо «Старт». Выполняется ровно один шаг алгоритма, анимация остаётся на паузе.
- **5а. Пауза.** Пользователь нажимает «Пауза». Анимация останавливается на текущем шаге, «Старт» продолжает её с этого места.
- **5б. Сброс.** Пользователь нажимает «Сброс». Массив возвращается в исходное состояние, счётчики обнуляются.
- **2а. Неизвестный алгоритм.** Пользователь открывает адрес с несуществующим идентификатором, например `/algorithms/abc`. Приложение показывает сообщение «Алгоритм не найден» и ссылку на список алгоритмов.

## Use case 2. Сравнение производительности алгоритмов

**Актор:** пользователь.

**Предусловия:** пользователь находится на странице «Сравнение» (`/compare`).

**Основной сценарий:**
1. Пользователь выбирает размер массива и вид данных.
2. Пользователь нажимает «Запустить сравнение».
3. Приложение создаёт один массив и запускает на его копиях все шесть алгоритмов без анимации.
4. Приложение выводит таблицу: для каждого алгоритма число сравнений, число перестановок и время выполнения в миллисекундах.

**Результат:** пользователь видит, какой алгоритм быстрее на выбранных данных, и может сопоставить это с теоретической сложностью.

## Границы MVP

### Входит в первую версию
- шесть алгоритмов сортировки: пузырьком, выбором, вставками, слиянием, быстрая, пирамидальная;
- пошаговая анимация массива с цветовой подсветкой сравнений, перестановок и отсортированных элементов;
- управление анимацией: старт, пауза, шаг, сброс, новый массив;
- настройка размера массива (5-100 элементов), скорости и вида данных: случайный, отсортированный, обратный, почти отсортированный;
- счётчики сравнений и перестановок;
- страница сравнения с таблицей результатов: сравнения, перестановки, время;
- справка по сложности каждого алгоритма.

### Не входит в первую версию
- шаг назад по анимации;
- ввод собственного массива вручную;
- диаграмма результатов сравнения (в MVP только таблица);
- отображение и подсветка кода или псевдокода алгоритма;
- одновременная анимация нескольких алгоритмов рядом;
- алгоритмы, не основанные на сравнениях: подсчётом, поразрядная;
- сохранение результатов, учётные записи, серверная часть;
- английский интерфейс и мобильная вёрстка.
